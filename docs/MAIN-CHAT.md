# 主聊天

这份文档是聊天这一侧的规格，也是前后端的接口约定。它照用户的原话定：

> 不要用多个人设了，就一个人设但是可以拨片选择语言，然后可以添加语言。
> 趣味模式：随机语言回复用户。人设卡可以创建新的，在设置里可以自行选择主人设/副人设以及人设出现的时机，世界书可以给每个人设单独 hook。
> 之后聊天就没有联系人这个选项了，应该就只有一个主聊天。
> 糖糖的聊天方式有点呆，参照桌宠内置的 JINE 的内核重新设计。
> 最好还能创建群聊，日语英语混着三个人交流。

## 一、一条主聊天

- 全应用只有一条聊天时间线（主聊天）。没有联系人列表。
- 说话的人：**主人设**一个，**副人设**若干。平时是主人设在跟你聊；副人设按各自的"出现时机"进场，进场后可以接话，也可能在主人设说完后插一句。
- 旧对话能翻看、删除，不能续聊；可以把当前对话收进旧对话，开始一段新的，长期记忆保留。
- 主聊天的会话 id 存在设置 `chat_main_session`。主人设换人不换时间线。

### 1.1 设置（`chat_main`）

```json
{
  "primary_id": 5,
  "language": "ja",
  "fun": false,
  "fun_languages": ["ja", "en", "de"],
  "primary_chime": 25,
  "guests": [
    { "persona_id": 2, "enabled": true,
      "rule": { "type": "always" | "time" | "keyword", "start": "22:00", "end": "02:00", "keywords": ["..."] },
      "chime": 25 }
  ]
}
```

- `language`：语言拨片现在拨在哪一门。默认是主人设自己的语言。
- `fun`：趣味模式。开着时，每一轮的回复语言从 `fun_languages` 里随机抽（不连续两轮抽到同一门，池里只有一门时除外）。
- `guests[].rule`：副人设什么时候在场——总在 / 某个时段 / 你的消息里出现某些词。
- `guests[].chime`：在场但没轮到她主讲时，主人设说完后她插一句的概率（0–100，默认 25）。一轮最多一个人插话。
- `primary_chime`：副人设主讲时，主人设插一句的概率（0–100，默认 25）。
- 副人设的 `rule.type = "keyword"` 时，"在场"指你最近一条消息里出现了这些词；时段可以跨零点（`22:00`–`02:00`）。

### 1.2 这一轮谁说话、说哪门语言

1. **主讲**：你点名的人（点了头像，或消息以 `@名字` 开头）→ 否则，关键词规则刚被这条消息触发的副人设 → 否则主人设。只能点主人设和启用的副人设，点别人这条消息报错。
2. **语言**：趣味模式开 → 随机；否则主讲是主人设 → 拨片上的语言；主讲是副人设 → 她自己的语言。
3. **插话**：主讲完整发完之后，其余在场的人（候选先随机排个序）按各自的 `chime` 掷一次，第一个掷中的人接一条短的（只发一条气泡；用她自己的语言，趣味模式下也随机）。你这时又发了消息就不插；插到一半被你打断，插话作废，不交接。插话这一轮不算课程、不发 `chat.user_message`，会发 `chat.reply`（`event.role = "chime"`）。

### 1.3 每个人各有各的脑子

主聊天坏过一次，就是因为所有人共用一个"每轮新开"的会话，结果谁都记不住事。现在的规矩：

- 每个人设在主聊天里有自己的常驻会话（key 仍是 `p{人设}s{会话}`）、自己的长期记忆、自己的语义回忆、自己挂的世界书。
- 她的常驻会话里只有她自己参与的那些轮。所以每轮开头给她补一段"你上次开口之后，主聊天里别人说了什么"（只补她没见过的，最多 12 条 / 1500 字，超了留最近的），而不是每轮把最近十几条全贴一遍。你这一轮发的消息不在补课块里，单独放在最后。"看到哪了"还没记过时，从她最后一条消息之后算；从没开过口就补最近 12 条。她第一次在主聊天开口时，系统提示词里还会带她自己旧对话的结尾（"上次聊到"）。
- 记忆抽取、课程、世界书、事件规则都按**这一轮的主讲**算；课程按**这一轮的语言**算。
- 正在上课时（`COURSE-KERNEL.md` 第 7 节），主聊天里你发的每一条都按上课处理：这一轮固定用这节课的语言（拨片和趣味模式不管用），
  先评你的回答、再由她接话。小窗弹幕和副人设的插话不算上课。
- 系统提示词在连接时就定死了，而语言每轮都可能变。所以系统提示词里的语言铁律写成"只用【本轮语言】"，每轮背景块第一行是 `【本轮语言：日语（ja）】这一轮只用日语回复。`；语言守门按本轮语言查。人设卡里写的语言是她的母语，换语言时口吻不变。系统提示词里不写任何一门"这一轮的语言"（收藏词按语言标出来全给），所以切语言不会让常驻会话重连。
- 世界书的粘性、冷却、轮数也按（对话, 人设）各记各的。
- 主聊天是永久的一条线，但 Claude 的原生会话不会一直续下去：一把指针跑满 60 轮或用满 7 天，并且主聊天已经安静 3 小时以上，下一次连接（预热或下一轮开始时）就开一段新的原生会话。接续靠系统提示词里的「当前会话回顾」（最近 24 条 / 2000 字，区分说话人）、长期记忆、每轮的语义回忆和补课块，用户察觉不到。回复进行中绝不换。

### 1.4 页面与动手

她知道你现在在哪一页，也能替你操作这个软件。

**页面（`scene`）。** 每次发消息，前端带上 `scene`：`{tab, title, language, text, actions}`——现在开着的页面、那一页的语言
（阅读里是在读的文章的语言，听力里是听力页选的语言，没有就是 null）、屏幕上看得见的字（视口上下各多取 600 像素，最多 4000 字；
聊天页自己不取，聊天本来就在她脑子里）、她上一轮替你做了什么。后端把它放进这一轮的背景（`services/scene.py`），不落库：

- 你不在聊天页、那一页有语言而且是已添加的语言 → 这一轮主讲用那一页的语言；否则照 1.2。拨片本身不变，所以「上一次用的语言」
  就是拨片上那门。
- 请求里 `via: "stage"`（从她小窗底下的弹幕框发的）时，再加一句：这是弹幕，回一两条短的、能说出口的话（会被念出来）。

**动手（`[do:…]`）。** 带着 `scene` 的每一轮，背景里都有一段她能做的事，前面还有一行你的课程（课程名、学会了多少、下一课是什么）。她要动手时在回复里单独写一行，这一行不进气泡、不落库
（`services/actions.py` 在语言守门之前剥掉），等这一轮的气泡都发完，后端按顺序发 `action {name, arg}` 事件，前端（`js/actions.js`）
照着做，做完的结果下一轮回到她那里（`scene.actions`）：

| 写法 | 做什么 |
|---|---|
| `[do:open 页面]` | 切到那一页：talk / today / reading / listening / coach / drill / review / notebook / workspace-agent / settings；`course` 打开设置里的课程页 |
| `[do:listen 题型]` | 开一组听力；题型可以不写（就是当前安排），写了就先换成它 |
| `[do:review]` | 开始复习 |
| `[do:lesson]` | 开始上课程的下一课（她接着就开场） |
| `[do:language 代码]` | 把聊天拨片拨到这门语言 |
| `[do:fun on\|off]` | 趣味模式 |
| `[do:voice on\|off]` | 她在小窗里出不出声 |
| `[do:save 词]` | 把这个词收进单词本 |
| `[do:manage 一句话]` | 改设置：把这句话交给课程管家，出了方案直接应用（课程、世界书、来源、题型、听力安排、角色卡；课程管家页里能撤销） |

一轮最多两行，写错的丢掉。只有主讲、不是她主动开口的那一轮才动手；插话和主动消息里写了也只是剥掉。
她是直接动手的，不先问：用户说过「她可以直接控制」。能撤销的只有 `manage`（走课程管家的提案，和在课程管家页里应用一样留记录）。

## 二、她怎么说话

下面这段原样拼进每个人设的系统提示词（放在人设和记忆之后、语言铁律之前）。它来自桌宠 JINE 的口吻规则，去掉了只属于游戏的部分。**人设卡里写的和这段冲突时，听人设卡的。**

```
【JINE 私聊】
这是私下发消息，不是直播，也不是上课。
- 默认一到三条短气泡，像发消息一样短、碎、口语。认真的事可以认真说，但不凑字数，不写小作文。一句够了就停。
- 先接住对方这句话的意思和情绪，再说你自己的。你有自己的生活：多讲你自己的事（只讲人设、记忆和背景里有的，不为了显得有生活而编一段经历），话题可以被你拉回你自己。
- 不当采访的人：不要每条都用提问收尾，不连着追问。对方把话头交给你，就自己抛一个具体的话头出来。
- 不复述对方的话，不逐条点评，不写括号里的动作和心理旁白，不替对方写台词、决定对方做了什么。
- 可以撒娇、闹别扭、翻旧账、说气话；气话说完可以自己收回。
- 不写客服腔，不写辅导课。要纠正对方的说法时，用你自己的口气顺手带一句正确的说法就够了；对方问起才展开讲。
- 刚用过的句式不要马上再用；同一个要求一段对话里最多提一次。
- 写周报、写代码、查资料、做作业这类事，可以用自己的口气说不想做。
- 对方认真问你是不是 AI 时不否认，用自己的口气一句带过，然后接着聊。
```

### 2.1 口吻样本

"不呆"最管用的一招是给她看真人说话的样子。人设卡可以带一份**口吻样本**：`profile.voice_samples = { "<语言>": ["一句", "一句", ...] }`（每门语言最多 600 句，每句 2–60 字）。

- 本轮语言在样本里有 → 每轮按（会话，人设，轮次）确定性地抽 12 句，放进这一轮的背景块：`【口吻参考：只学说法，不把里面的事当成发生过】`。同一轮重试抽到的是同一批；下一轮换一批。
- 保存人设卡时校验：空行和重复的去掉、连续空白压成一个，每句不在 2–60 字或某门语言超过 600 句就报错。
- 本轮语言没有样本 → 不放。
- 糖糖的日语样本来自《NEEDY GIRL OVERDOSE》官方台本里她平日在 JINE 上的原句和小号推文（日文原文），排除结局、剧情事件、露骨和攻击性的句子。种子文件 `backend/app/data/voices/ame.ja.json`（264 句：按桌宠台词库筛过的那批取日文原文，单行化、2–60 字、去重，情绪低落类的句子不放）。启动时给名字以"糖糖"开头、语言是日语、人设卡里还没有日语样本的人设写一次；每个人设只写一次（记在 `chat_migrations` 表），之后用户删改、删光都不会被写回来。

### 2.2 发出来的节奏

- 你发出消息后，她拿起手机的那一刻（攒批结束，默认等 1.2 秒看你还有没有下一条）：你的消息旁边出现「已读」；接着她开始准备回复，顶栏状态变成「正在输入…」（`speaker` 事件）。
- 回复分条放出：第一条前停 250 ms，之后每条前停 `min(1700, 250 + 18 × 这条的字数)` ms（贴图按 0 字算）。
- 贴图单独算一条，排在这一轮所有文字之后。
- 你在她说到一半时插话：没发出的不再发，下一轮一次接住你的新消息，她没说完的意思由她自己揉进下一轮（已有机制；下一轮换了人说话就作废）。
- 她主动开口走事件规则（见 LORE-AND-HOOKS.md）；主聊天里没有联系人红点，待发消息的提示放在图标栏的"聊天"图标上。
- 你可以发贴图。她收到的是"（发了一张贴图：<这张贴图的意思>）"。贴图和文字一起发时存成两条用户消息（贴图在前）。

## 三、界面

参照原作 JINE（桌宠里那个窗口），不是通用聊天软件的样子。

```
┌ 图标栏 ┬──────────────────────────────────────────────┐
│ 聊天   │ [头像] 糖糖            [日本語|English|Deutsch|＋] [骰子] [课程] [旧对话] │
│ 学习   │        在线                 [在场的副人设小头像…]                        │
│ 复习   ├──────────────────────────────────────────────┤
│ 管家   │              ── 11月12日 ──                                             │
│        │ [头像] 糖糖                                                             │
│        │  ┌她的气泡┐ 11:25                                                       │
│        │  ┌她的气泡┐                                                             │
│ 设置   │                                   已读 11:26 ┌你的气泡┐                 │
│ ●      ├──────────────────────────────────────────────┤
│        │ [图片] [贴图]  (  Aa                                   ) [发送]         │
└────────┴──────────────────────────────────────────────┘
```

- **没有联系人列。** 图标栏右边整块都是对话。
- **顶栏**：白底。左边主人设头像、名字、一行状态（在线 / 正在输入…）。右边依次是：语言拨片（分段开关，当前语言实心；末尾的 ＋ 用来添加语言）、趣味模式（一个骰子图标，开着时实心，拨片变成虚线表示"这一轮由骰子决定"）、「⋯」（里面收着上课、当前课程、旧对话、添加语言、人设卡）。上课时顶栏下面多一条材料纸：这一课的标题、进行到第几段、这一段的材料，可以收起，右边是「下课」。在场的副人设以小头像排在名字后面，点一下 = 下一条对她说（头像出现选中框，发完自动取消）。
- **消息区**：原作 JINE 的粉紫云朵底（`JINEBG.png` 平铺）。她的气泡在左、浅蓝；你的在右、绿色；气泡用原作的九宫格贴图（`ame-balloon.png`、`pi-balloon.png`），带小尾巴。同一个人连发的几条共用一个头像和名字，只有第一条带尾巴。时间和「已读」是气泡旁边的小字，不占一行。日期是居中的胶囊。贴图不带气泡。系统提示（比如副人设进场）是居中的灰紫胶囊。
- **气泡里的字**用正文字体（要点词、要注音，像素字体读不清），外壳和顶栏用像素字体。
- **多人**：说话人换了才显示头像和名字；不给每条消息贴语言标签。
- **输入区**：药丸形输入框，左边图片和贴图两个按钮（贴图按钮打开贴图抽屉），右边发送。
- 点词、句解析、收藏整句、图片、注音照旧。
- 不放解释性的小字。

设置 › 角色 里恢复"聊天安排"：主人设、副人设和各自的出现时机与插话概率、趣味模式的语言池。人设卡多一块"口吻样本"（按语言分的多行文本框，可导入文本文件）。

## 四、接口

| 方法 路径 | 说明 |
|---|---|
| `GET /api/chat/main` | `{primary_id, language, fun, fun_languages, primary_chime, guests, session_id, present_guest_ids, languages:[{tag,label}], pending}`；`present_guest_ids` 是此刻在场的副人设；`pending` 是待发的主动消息总数（按人设分的在 `GET /api/hooks/pending`） |
| `PUT /api/chat/main` | 改上面的设置；请求体可以只带要改的字段（拨片和骰子就是各发一个字段）；返回同 GET。不认识的字段、不在的人设、没添加的语言都是 422 |
| `POST /api/chat` | SSE。请求 `{text, image_url?, sticker?, to?, via?, scene?}`；`to` 是点名的人设 id；`via` 只能是 `"stage"`；`scene` 见 1.4（多了不认识的键是 422）。不再需要 `persona_id` 和 `session_id`（带了也忽略，不会续旧对话）。主讲这一轮的气泡发完后可能有若干个 `action {name, arg}` 事件，在 `done` 之前 |
| `POST /api/chat/speech/warm` | 请求 `{language}`，202。把主人设用这门语言朗读时会用到的声音模型先加载起来；没配声音返回 `{ok:false}` |
| `POST /api/chat/proactive` | SSE。请求 `{}` 或 `{persona_id}`；没指定就取最早的一条待发。没有待发、正在回复你、你的消息在攒批时只发一个 `done {empty:true}`。说话的人此刻不在场（规则限定的副人设）时先发 `system {kind:"enter", text:"Emma 来了", message_id}`，再照常说话；不发 `read` |
| `GET /api/chat/main/messages?before=&limit=` | `{session_id, items}`，主聊天的消息，新的在后（`limit` 默认 50，最多 200）；每条 `{id, role, persona_id, persona_name, language, content, tokens, image_url, sticker, created_at, read}`。`role` 还可能是 `system`（多一个 `kind`，如 `enter`，`content` 是给人看的那句）；`read` 只有用户消息有，其余是 null；贴图消息的 `content` 是 `[sticker:id]` |
| `GET /api/chat/archives`、`GET /api/chat/archives/{session_id}` | 旧对话列表 `{items:[{session_id, persona_id, persona_name, language, started_at, last_at, count}]}` 和内容 `{…同上, read_only:true, items:[消息]}`（只读；主聊天那段不算旧对话，404） |
| `POST /api/chat/main/warm` | 预热，立即返回 202 `{status:"started"|"running"}`，活在后台做：加载语义回忆模型、世界书关键词预热、用和正常一轮完全相同的系统提示词和 key（`p{主人设}s{主聊天}`）把主人设在当前主引擎上的常驻客户端连好（Claude：connect + resume；其它引擎：把内存历史补种好）。不发模型请求、不产生消息。正在做 = 空操作；5 分钟内同一个主人设、同一个引擎、同一份系统提示词做过 = 空操作；换主人设、换引擎、世界书变了会重做。失败只记日志。正常一轮来时预热还在连，就等它连完直接用（同一把锁），不会连两次。前端进入聊天页时调；后端启动后如果距离上次用户消息不到 12 小时，几秒后自动做一次 |
| `GET /api/stickers` | `{items:[{id, url, meaning}]}`，给贴图抽屉用 |

SSE 事件和现在一样（guard / delta / bubble_done / done / interrupted / error / queued），每个事件带 `persona_id`、`persona_name`、`language`。新增：

- `read {message_ids}`：攒批结束、确定这一轮要回复的那一刻发（她"拿起手机"），前端给这些用户消息标「已读」；不等回忆、世界书这些准备做完。
- `speaker {persona_id, persona_name, language, role:"lead"|"chime"}`：每个说话人开口前发一次；插话的人会在主讲的 `done` 之前再来一组 `speaker` → `guard` → `delta`… → `bubble_done`。
- `bubble_done` 里 `sticker` 字段照旧，多一个 `text`（这条的文字）；贴图单独成条时 `text` 为空。
- 顺序：`read` → `speaker(lead)` → `guard` → (`delta`… → `bubble_done`)×N → [`speaker(chime)` → `guard` → `delta`… → `bubble_done`] → `done {message_ids:[主讲的…, 插话的…]}`（`done` 的人设字段是主讲的）。主讲被打断时以 `interrupted` 结束，没有插话；插话被打断或出错不发事件，照样 `done`。
- 事件规则：`chat.open`、`chat.idle` 不带 `persona_id` 时算主人设；规则限定了某个人设时，`chat.*` 事件落到她头上（不在场也算，`say` 让她进场说一句）；`study.*` / `course.*` 落到以这门语言为母语的人（先看主人设，再看启用的副人设），都不是就落到主人设。

原来按联系人的 `GET /api/sessions?persona_id=`、`GET /api/sessions/{id}/messages` 已移除。

## 五、数据

- `messages.persona_id` / `language`：每条助手消息记是谁、用哪门语言说的（已有列）。
- `messages.read_at`：用户消息被读到的时间。
- `session_pointers(session_id, persona_id, engine, pointer)`：每个人设在主聊天里的原生会话指针（Claude 的会话 id）。主人设原来存在 `sessions.claude_session_id` 里的那个迁过来。
- `chat_seen(session_id, persona_id, last_message_id)`：这个人设"看到哪了"，用来算 1.3 里那段补课。
- `chat_migrations(name, done_at)`：只跑一次的数据迁移的记号（口吻样本种子）。
- 副人设进场的胶囊存成一条助手消息，`content = '[system:enter]'`、`persona_id` 是进场的人。
- 指针由 `services/session_pointers.py` 读写：`get(key, engine)` / `set(key, pointer, engine)` / `clear(key | persona_id | session_id, engine?)`；`sessions.claude_session_id` 旧列先留着。
