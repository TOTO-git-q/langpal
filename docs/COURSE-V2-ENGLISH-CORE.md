## 教学方式：理解和产出都要有

七段 `practice` 是后台可选择的策略，不是每次聊天必须执行的机械流程：

1. `entry` 抓住用户当前真的在聊的事；不相关、用户不愿意或求情绪支持时暂停教学。
2. `input` 明确本单元应提供什么材料以及已知条件，不能让模型要求用户猜材料没给的事实。
3. `noticing` 只让用户注意会改变意义的一处差异，如 some/all、查询/已确认、关联/因果。
4. `supported` 先具体追问，再关键词或结构，最后示范；帮助程度是评价输入，不能抹掉。
5. `independent` 撤去目标提示，更换材料或角色，要求真实的理解或表达行动。
6. `transfer` 把同一语言带入朋友、管理员、同伴等新沟通场景；保留考试专项的独立入口。
7. `retrieval` 在分开的有效练习机会里换条件提取。间隔归课程当前 `teaching_policy`，不按日历、不在单元里写死 3/8/20。

来源支持的是技能范围与活动选择，并未规定这 61 个应用单元的唯一正确次序。单元拆分、场景、先修关系、原创材料、四档 rubric 和默认掌握门槛都是 JINE 作者决定，允许用户以后编辑，不宣称经过教育测量标定。次数只是证据门槛；不能用练习次数、命中关键词或背出示例自动判掌握。

## 声学与模式边界

- 所有 pronunciation 知识点的必需 criterion 均 `requires_audio: true`。输入音频用于核对听辨，用户录音用于核对发音，二者不能互相代替。
- 纯文字可练语法、词义、结构和表达；无音频时不能判断重音、停顿、词尾可辨度或流利度。
- 两个 Listen and Repeat 单元的 typed 任务明确只是复原、分组或规划准备；不能满足其声学/复述标准。真实口语复述需原音频和用户录音。无音频缺证据应保持未评价，而非判错或算成功。
- 自由改述在真实交流中可成功，但不替代固定词块重建、缺字拼写或原样复述的输入约束。
- 口语题中可评价文本内容的知识与有音频才可评价的知识分开；不能从 ASR 的字面一致率认定读音准确。
- CET 的口头任务来自大学英语综合运用目标，是迁移练习，不冒充 CET 笔试的新增口语题，也未标成 CET-SET 官方教案。
- 应用四档不换成 ETS 分数、CET 分数、CEFR 认证或“TOEFL110已达成”。

## 生产、审阅与验证

作者源：[authoring/english_core.py](../authoring/english_core.py)。脚本不调用 LLM、联网、数据库、密钥或正式运行目录，只确定性生成三份数据。通用 helper 负责 schema 包装和四档共同语义，实际每点的形式、例句、误解、观察标准、灵活迁移条件，以及每单元七段策略、两个情境和探测均逐项给出。

```powershell
python authoring/english_core.py
python authoring/english_core.py --check
python -m unittest discover -s tests -p test_course_v2_english_core.py -v
```

`--check` 不改文件，比较实际 JSON 与作者源的逐字节生成结果。每份文件同时实跑 `CourseV2.model_validate_json` 与 `Draft202012Validator`，不会仅凭字段看起来完整宣称通过。

专项测试检查旧 ID/顺序、先修拓扑、双 schema、重建一致、每点两条目标语例句、逐点必需四档标准、两情境与双模式覆盖、全部七段非空且各单元不同、声学证据门槛、当前 TOEFL 全部任务名称和考试/迁移边界。测试是课程数据合同检查，不证明真实学习成效。

人工复读以每点的“能观察什么/典型误解是什么/换情境后怎样才算灵活”为准，尤其检查固定输入任务与自由表达不同、否定和条件不反向、例子不冒充研究结果、中文翻译不增译成效。邮件单元先交独立质检，确认具体知识与模式差异后才完成批量生产。最终只冻结这三份教案和可重跑作者源；运行接入、数据库迁移和正式部署由集成任务另行负责。
